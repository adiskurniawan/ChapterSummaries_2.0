Foundations of Deep Learning and Machine Learning
1. Q: What is deep learning, and what distinguishes it from other approaches to machine learning?
A: Show answer
Deep learning is a subfield of machine learning concerned with training neural-network models that contain multiple processing layers. The layers learn representations at different levels of abstraction: early computations can respond to relatively simple patterns in the input, while later computations combine those patterns into more task-relevant representations. The trained network maps complex inputs, such as pixels, audio signals, or text, to outputs such as classifications, predictions, translations, or actions. Its distinctive contribution is not simply that it uses a large model; it is that the model can learn useful intermediate representations from data rather than relying entirely on people to specify every feature in advance. Deep learning is especially useful when inputs are complex and sufficiently large, representative datasets and computational resources are available. It is not automatically the best choice for every problem: a simpler model may be easier to validate, explain, and maintain when the data or task is modest.

- Explain the roles of multiple layers, learned representations, training data, and task-specific outputs without defining deep learning merely as a large neural network.
Key point:
- Deep learning learns hierarchical representations through multilayer neural networks.
- Its advantage depends on the task, data, compute, and evaluation conditions.

2. Q: How are artificial intelligence, machine learning, and deep learning related?
A: Show answer
Artificial intelligence (AI) is the broad field concerned with building systems that perform tasks associated with intelligent behaviour, such as perception, reasoning, planning, language processing, and decision-making. Machine learning (ML) is one approach within AI: instead of specifying every decision rule manually, developers use algorithms that infer patterns or functions from examples or interaction. Deep learning is a specialised family within ML that uses multilayer neural networks to learn representations and mappings. The relationship is therefore nested in the usual conceptual taxonomy: deep learning is part of machine learning, and machine learning is part of AI. Not all AI systems learn from data, not all machine-learning systems use neural networks, and not all neural networks are deep. Rule-based expert systems, decision trees, linear models, and deep neural networks illustrate different approaches within the broader AI landscape. The distinction matters when describing a system accurately, selecting a method, or assessing what evidence is needed to trust its output.

Key point:
- AI is the broad field; ML is a data-learning approach within it.
- Deep learning is the multilayer-neural-network branch of ML.

3. Q: What does it mean to represent a machine-learning task as a function?
A: Show answer
A function describes a mapping from input values to one or more output values. In a loan-risk example, inputs might include verified income and existing debt, while the output might be a risk score or a predicted category. In speech recognition, the input is an audio signal and the output is a text sequence. In image analysis, the input is an image and the output might be a label, a set of object locations, or a pixel-level segmentation. This formulation helps separate the problem's inputs from the result the system is expected to produce. A conventional feed-forward model with fixed parameters gives the same output for the same input, although real-world outcomes may be uncertain and a model may output probabilities or a distribution rather than a single hard label. The function view is useful because it gives a common description for tasks that otherwise look very different and makes it possible to specify what the model should learn and how its output should be evaluated.

- For spam detection, face analysis, speech transcription, and translation, write down the input representation and the intended output separately.
Key point:
- ML seeks a mapping that captures useful relationships between inputs and outputs.
- The output type must be defined before choosing a model or metric.

4. Q: What are a dataset, an instance, a feature, and a target?
A: Show answer
A dataset is a collection of examples used to develop or assess a model. In a tabular representation, each row commonly represents an instance (one example), and each column represents a feature (one recorded attribute). In supervised learning, one field or structured output is designated as the target: the value the model is intended to predict. For example, a loan dataset might contain income and debt as input features and a historically determined repayment outcome as the target. An identifier used only to distinguish records is not automatically a meaningful predictive feature; including identifiers can cause a model to memorise accidental patterns. For images, audio, or text, the raw data may not initially look like a conventional table, but the same conceptual distinction remains: each example has an input representation and, where supervision is used, an associated target. Dataset design must also record units, definitions, collection dates, provenance, and missing-value conventions so that a column has a consistent meaning across examples.

- Take a small tabular dataset and label its instances, input features, target, identifiers, units, and any missing-value indicators.
Key point:
- Features describe examples; a target states what supervised learning should predict.
- Poor definitions or inconsistent records undermine every later modelling step.

5. Q: What does a machine-learning algorithm search for when it learns from data?
A: Show answer
A learning algorithm searches among candidate functions for one that performs well against the examples and the chosen measure of fitness. The set of candidate functions is often called the hypothesis space or model class. It may be stated explicitly, as when a toy exercise allows only addition, subtraction, multiplication, or division, or be implied by the model architecture and learning procedure, as with a neural network. The algorithm is not discovering an unconstrained truth from nothing: its search is limited by the functions it can represent, the data it receives, the objective it optimises, and assumptions built into its design. These constraints are useful because an unrestricted search is generally impossible, but they can also prevent the model from representing the real relationship. A sound project therefore asks whether the candidate model class is expressive enough for the task and whether its assumptions are appropriate for the data-generating process.
Study instruction:
- Compare a four-operation toy hypothesis space with a linear-model hypothesis space and a neural-network hypothesis space; identify what each can and cannot represent.
Key point:
- Learning is a constrained search over candidate mappings.
- Model design determines which patterns can be represented.

6. Q: How do an algorithm, a model, a function, parameters, and hyperparameters differ?
A: Show answer
The algorithm is the procedure used to fit a model. The model is the learned representation that can be executed to produce outputs; mathematically, it encodes a function. Parameters are values learned from training data, such as weights and biases in a neural network. Hyperparameters are settings selected outside the ordinary parameter-update process, such as architecture depth, learning rate, batch size, or regularisation strength. These terms are related but not interchangeable. Changing the training algorithm can produce a different fitted model even with the same architecture, while changing hyperparameters changes the conditions under which fitting occurs. Once a trained model is deployed, its parameters are normally held fixed for that model version, even though a later retraining cycle may produce a new version. Precise terminology helps teams distinguish model development, configuration, evaluation, and release decisions.

- In a neural-network example, identify the training algorithm, architecture, learned weights, and two hyperparameters; explain which values are learned and which are configured.
Key point:
- The algorithm performs learning; the model is the learned executable mapping.
- Parameters are learned, while hyperparameters govern the learning setup.

7. Q: What happens during model training?
A: Show answer
During training, the learning procedure repeatedly uses examples to adjust model parameters so that the model's outputs improve according to a defined objective. In a supervised setting, the model receives an input, produces a prediction, and that prediction is compared with the known target. The resulting error or loss provides a signal for changing the parameters. A randomly initialised neural network will usually begin with poor task performance; repeated parameter updates can make its mapping more useful. Training is therefore an optimisation process guided by data and an objective, not a process in which the network is explicitly given a complete set of human-written rules. The quality of training depends on representative data, appropriate labels, a suitable architecture, a meaningful objective, and a procedure that can optimise the parameters. A low training loss alone does not prove that the model will work well on new examples.
Study instruction:
- Trace one supervised training example through input, prediction, comparison with target, loss calculation, and parameter update.
Key point:
- Training changes model parameters using a learning signal derived from data.
- Training performance must be distinguished from performance on unseen examples.

8. Q: What is inference, and how does it differ from training?
A: Show answer
Inference is the use of a trained model to produce outputs for new inputs. During ordinary offline training, parameters are updated using a training objective; during ordinary inference, the deployed model applies its learned mapping without changing those parameters. For example, after training a speech-recognition model, a device can use it to transcribe a new audio recording. The new recording may have no known target available at the time of prediction, which is why the output is an estimate rather than a verified answer. Training and inference also require different operational capabilities: training requires data preparation, experimentation, and model evaluation, while production inference requires reliable serving, latency management, security, monitoring, and integration with the surrounding workflow. This distinction is not absolute for every learning paradigm: reinforcement learning and some online-learning systems interleave action selection and further learning. Teams should document which model version generated each production result and when it was updated.

- Describe the lifecycle of a trained classifier from completed training to a prediction on a new record, noting where parameter updates stop and where operational monitoring begins.
Key point:
- Training fits the model; inference applies the fitted model to new inputs.
- Production deployment adds reliability, monitoring, security, and version-control responsibilities.

9. Q: Why is learning a function from a small set of examples an ill-posed problem?
A: Show answer
A problem is ill-posed in this context when the available examples do not uniquely determine the underlying function. Many different candidate functions may agree with every observed example but produce different outputs for inputs that were never observed. In the chapter's arithmetic illustration, a limited set of input-output pairs can be consistent with both multiplication and division, so the observations alone do not identify which rule generated them. More data may distinguish the candidates, but additional examples may be expensive or unavailable. The learning algorithm therefore needs assumptions that favour some candidate explanations over others. This is a fundamental reason that model predictions are not guaranteed truths: the training evidence is finite, and the model's answer depends partly on the assumptions and representation used to interpret that evidence.

- Construct two different functions that agree on a few sample points but diverge on a new point; explain why the samples cannot identify the true rule.
Key point:
- A finite dataset usually supports multiple plausible explanations.
- Generalisation requires assumptions in addition to observed examples.

10. Q: What is inductive bias, and why does every learning algorithm need it?
A: Show answer
Inductive bias is the set of assumptions that influences which functions a learning algorithm prefers when it generalises from specific examples to new cases. A dataset supplies observations, but it does not usually specify a unique rule for every possible input. Bias supplies a perspective: a linear model favours linear relationships, while a neural network permits a much broader range of mappings. The bias is not necessarily a flaw or a social prejudice; in this technical context it is a modelling assumption that makes learning from finite evidence possible. If the assumptions match the domain, they can improve generalisation and reduce the amount of data needed. If they are inappropriate, the model may systematically miss important structure or fit accidental patterns. Model selection is therefore partly the task of finding assumptions that align with the problem rather than searching for a universally best algorithm.

Key point:
- Inductive bias helps a model generalise beyond the examples it has seen.
- A useful bias is appropriate to the domain, not universally superior.

11. Q: How can a strong inductive bias cause underfitting?
A: Show answer
Underfitting occurs when the model is too restricted to capture important patterns in the task. A strong inductive bias can cause this when it forces the learner to prefer a simple form that cannot represent the real relationship. For example, a strictly linear model cannot accurately describe a strongly curved relationship unless useful transformations or additional structure are introduced. Underfitting is often visible as poor performance even on the training data, because the model cannot fit the relevant pattern in the examples it was given. The remedy is not automatically to choose the largest possible neural network. A better response is to investigate whether the input features, model class, and assumptions are appropriate, and then increase expressive capacity or revise the representation in a controlled way. The decision should be supported by training and validation evidence.
Study instruction:
- Fit or sketch a straight line against a curved pattern and identify the systematic residuals that indicate the model class is too limited.
Key point:
- Underfitting is a failure to capture relevant structure, even in the training sample.
- Increase or redesign model capacity only when evidence indicates the current representation is inadequate.

12. Q: What is overfitting, and why is it a particular concern for flexible neural networks?
A: Show answer
Overfitting occurs when a model fits details of the training sample that do not represent stable relationships in the wider population. These details may include random noise, unusual records, duplicates, or correlations that arise by chance. A flexible model can achieve very low training error by fitting such details, yet perform poorly on new examples. The chapter highlights that neural networks can have relatively weak inductive bias and substantial representational flexibility, making overfitting a concern when the amount or diversity of data is insufficient. Overfitting is not diagnosed solely by a large model size; it is identified by a gap between training performance and performance on data that was not used to fit the model. More representative data, appropriate regularisation, a suitable architecture, careful validation, and better feature design can reduce the risk, but none guarantees success in every domain.
Study instruction:
- Compare training and validation performance across model versions and explain why a model with lower training error may still be the worse choice.
Key point:
- Overfitting is learning sample-specific noise rather than patterns that generalise.
- Flexible models need sufficient representative evidence and disciplined evaluation.

13. Q: How should a data scientist balance model complexity and inductive bias?
A: Show answer
The goal is to choose a model that is expressive enough to capture the meaningful structure but constrained enough to avoid fitting noise. A very simple model may underfit, while a highly flexible model may overfit if the dataset does not contain enough information to constrain it. The balance is empirical: compare candidate approaches using a validation process that reflects the intended use, examine error patterns, and test whether added complexity improves performance on data not used for fitting. Domain knowledge can guide the choice of features and architecture, while regularisation and other design constraints can discourage unnecessarily complex solutions. The appropriate balance can change as the task, population, data volume, or operating environment changes. It should therefore be justified by evidence rather than by a general preference for either simple or complex models.

- Useful model complexity is the amount supported by the task and evidence.
- Validation performance, not training fit alone, should guide selection.

14. Q: What does generalisation mean, and how can it be assessed?
A: Show answer
Generalisation is a model's ability to perform well on new examples drawn from the population or operating conditions relevant to its intended use. Training error measures fit to the examples used for parameter learning; it is not an unbiased estimate of future performance. A validation set can support model and hyperparameter selection, while a separate test set should be reserved for final evaluation after those choices have been made. The test examples should be representative, sufficiently numerous for the intended claim, and free of overlap or leakage from training. For time-dependent data, random splitting may be inappropriate if it lets future information influence a model intended to predict the past or present; the split should respect the deployment timeline. Generalisation is always relative to a data distribution, so a strong score on one benchmark does not prove performance in every country, population, device, or future period.
Study instruction:
- Design a training, validation, and test split for a time-stamped dataset and explain how it prevents future information from leaking into training.
Key point:
- Generalisation concerns unseen data relevant to the intended use.
- A protected test set is needed for a credible final performance estimate.

15. Q: Why is matching every training example exactly often the wrong objective?
A: Show answer
Real datasets contain measurement error, inconsistent labels, unobserved influences, and random variation. If a model is rewarded only for reproducing every recorded value, it may learn those sample-specific irregularities rather than the stable relationship that matters in practice. For instance, an unusual transaction may reflect a one-off data-entry error rather than a recurring behavioural pattern. A model that memorises such a record can become less reliable on new records. The objective should therefore reward useful predictive performance while controlling the tendency to fit noise. This requires reviewing data quality, selecting an appropriate loss function, evaluating on independent examples, and investigating outliers rather than automatically deleting or reproducing them. Some unusual observations are genuine rare events and may be important; their treatment should be based on domain evidence and the intended task.
Study instruction:
- Review a sample containing both a genuine rare event and a data-entry error; explain how each should be investigated before model fitting.
Key point:
- Exact training fit can reward noise and accidental patterns.
- Outliers require investigation, not automatic removal or automatic acceptance.

16. Q: What are the three key ingredients in a machine-learning project?
A: Show answer
The chapter identifies three essential ingredients: data, a set of candidate functions, and a measure of fitness. Data provides examples of the domain and the relationships the system is expected to learn. The candidate-function set defines what the learner is capable of representing and is shaped by the model and its inductive bias. The fitness measure evaluates how well a candidate function performs against the available evidence. A project can fail if any one ingredient is unsuitable. Incomplete or biased data can misrepresent the task; an overly restrictive model can miss relevant patterns; and a poorly chosen fitness measure can reward behaviour that is technically successful against the metric but harmful or unhelpful in practice. These ingredients should be designed together, with the intended decision and its consequences made explicit before training begins.

17. Q: How should a fitness measure or loss function be selected?
A: Show answer
A fitness measure converts model outputs and relevant evidence into a signal that allows candidate models to be compared. Its design must reflect the task. For continuous prediction, a measure such as mean squared error may be appropriate when large errors should receive a disproportionate penalty. For classification, accuracy may be useful when classes and error costs are balanced, but precision, recall, sensitivity, specificity, or a threshold-dependent measure may be more informative when false positives and false negatives have different consequences. In some tasks, the training loss is a mathematical surrogate that is convenient to optimise, while the operational evaluation metric measures whether the system meets the real requirement. These should not be confused. A metric can also be gamed or give a misleading average if the evaluation set is unrepresentative. Teams should document why the chosen measure fits the decision, what errors it hides, and which additional measures or human reviews are required.

18. Q: How does a neural network represent a function?
A: Show answer
A neural network represents a function through interconnected computational units commonly called neurons. Each unit receives numerical inputs, applies a parameterised computation, and passes an output to later units. The network's connections determine how information flows through the model, while learned parameters determine how strongly inputs influence subsequent computations. In a typical feed-forward network, information moves from an input representation through one or more hidden layers to an output layer. The network as a whole therefore composes many smaller functions into one larger mapping. The output might be a score, a class probability, a numerical prediction, or another structured result. The network diagram is a conceptual representation; practical models can contain many layers, parameters, branches, and operations that are not visible in a simple schematic.

Key point:
- A neural network is a parameterised composition of smaller computations.
- Learned parameters determine the mapping encoded by the network.

19. Q: Why can combining simple neural-network computations produce a complex function?
A: Show answer
A network uses a divide-and-conquer structure: individual units or groups of units learn intermediate computations, and later layers combine their outputs. In image processing, for example, early layers may respond to local visual patterns, while later layers can combine those patterns into representations associated with larger shapes or objects. In language tasks, representations can be combined to capture relationships among tokens or phrases. The usefulness of depth comes from this ability to build progressively more abstract representations, not simply from adding more layers for its own sake. A network with an unsuitable architecture, insufficient data, or poor training may fail to learn meaningful intermediate representations. Depth also adds design and computational complexity, so it should be justified by the structure of the problem and measured performance.

Key point:
- Layers build complex mappings by composing simpler computations.
- More depth is useful only when it supports the task and can be trained reliably.

20. Q: Why is deep learning especially useful for high-dimensional data such as images, audio, and text?
A: Show answer
High-dimensional data contain many input values or features. A photograph may contain a value for every colour channel at every pixel; audio can contain a large sequence of signal measurements; and text can contain long sequences of tokens. Hand-designing a useful set of features for such inputs can be difficult because relevant information may depend on complex combinations of many low-level values. Deep learning can learn intermediate representations directly from large collections of examples, reducing dependence on a fully hand-engineered feature pipeline. This capability has supported progress in image recognition, speech processing, and language tasks. It does not remove the need for data curation, domain expertise, or evaluation. A model may learn shortcuts, fail on unfamiliar conditions, or perform unevenly across populations if the training data do not represent the intended use.

21. Q: What is the difference between hand-engineered features and learned features?
A: Show answer
Hand-engineered features are designed or selected by people using domain knowledge and an understanding of the task. A derived feature such as body mass index combines weight and height into a ratio that may be more useful for a particular screening purpose than either raw measurement alone. Learned features are internal representations that a model discovers during training because they help reduce the task's objective. Traditional machine-learning workflows often depend heavily on human feature design, while deep learning can learn multiple levels of representation from raw or lightly processed inputs. The distinction is not absolute: deep-learning systems still rely on input definitions, data preparation, domain-informed design, and sometimes engineered features. A learned representation is only useful if the training data and objective encourage it to capture the right information rather than shortcuts or irrelevant correlations.

22. Q: What trade-offs arise when selecting features for a dataset?
A: Show answer
Including too few features can omit information needed to distinguish important cases. Including every available field can add irrelevant, redundant, unstable, or sensitive information that encourages spurious correlations and increases the risk of overfitting. Feature selection should combine domain expertise, examination of distributions and relationships, data-quality checks, and controlled experiments comparing model performance with and without candidate features. Correlation alone does not establish that a feature is causally relevant or safe to use. A field may also act as a proxy for a protected characteristic or encode historical decisions that should not be repeated. Feature selection is therefore both a predictive and a governance decision: the team should document why a feature is needed, how it was collected, whether its use is lawful and appropriate, and whether it remains valid over time.

- More features do not automatically produce a better model.

24. Q: What are the limitations of using BMI as if it were a complete description of health?
A: Show answer
BMI is a screening measure based on weight relative to height; it does not directly measure body fat, distinguish muscle from fat or bone, or show where fat is distributed. The CDC advises that individual BMI should be considered with other information such as blood pressure, cholesterol, and physical examination. It should not silently turn a screening category into a clinical diagnosis. Similar caution applies to any machine-learning feature that stands in for a complex social, biological, or economic condition.

25. Q: What is supervised machine learning?
A: Show answer
Supervised learning uses examples paired with known target outputs. The model receives the input features, generates a prediction, and compares that prediction with the target supplied for the example. The difference provides a learning signal that guides parameter updates or another search procedure. In a loan example, income and debt may be inputs and a defined repayment outcome may be the target. In speech recognition, audio recordings can be paired with reference transcripts. Supervision is valuable because the algorithm receives explicit information about the desired output, but collecting trustworthy labels can be expensive and difficult. Labels may require expert judgement, can contain disagreement, and may reflect historical practices rather than a fair or correct outcome. A supervised model learns to reproduce patterns in the labels, so label quality and target definition are central to model quality.

Key point:
- Supervised learning uses known target outputs to guide fitting.
- The model can inherit errors and biases in its labels.

26. Q: Why can obtaining labels for supervised learning be difficult or expensive?
A: Show answer
A target may not be directly observable, may become known only after a delay, or may require a qualified person to interpret the evidence. Medical images may need expert annotation; speech recordings may require transcription; and a loan outcome may not be known until a repayment period has elapsed. Label collection therefore consumes time and money and can introduce disagreement, inconsistent definitions, and selection bias. Before collecting labels, a project should define the target precisely, document the labelling instructions, specify how ambiguous cases are resolved, and measure agreement between reviewers where appropriate. It should also verify that labels are available for a representative range of cases, rather than only the easy or familiar examples. A large dataset with unreliable labels may be less useful than a smaller but carefully defined and validated dataset.

27. Q: How do classification and regression differ as supervised-learning tasks?
A: Show answer
Classification predicts a category, such as spam versus not spam or one of several image classes. Regression predicts a numerical quantity, such as a temperature, demand level, or credit-loss estimate. Both are supervised because training examples contain target values, but the output structure and appropriate evaluation measures differ. Classification may require threshold selection and analysis of false-positive and false-negative rates. Regression often requires examination of prediction error magnitude, calibration, and whether errors are systematically larger in certain ranges. A probability score from a classifier is not automatically a calibrated probability, and a numerical prediction is not automatically a reliable measurement. The task definition should state whether the decision needs a category, a score, a ranked list, or a quantity, and whether downstream users will apply a threshold or make a separate judgement.

- Classification predicts categories; regression predicts numerical values.

The logistic sigmoid is sigma(z) = 1 divided by (1 + exp(-z)). It maps every finite real input to a value strictly between zero and one. Near zero, its output changes smoothly with the input; for large positive inputs it approaches one, and for large negative inputs it approaches zero. This bounded range can be useful for a binary-probability output when paired with an appropriate probabilistic loss and interpretation. In hidden layers, however, saturation at either end can make gradients very small and slow learning.

21. Q: What is the hyperbolic tangent activation function?
A: Show answer
The hyperbolic tangent is tanh(z) = (exp(z) - exp(-z)) divided by (exp(z) + exp(-z)). It maps real inputs to values between -1 and 1 and is centered at zero: tanh(0) = 0. Its output is negative for negative inputs and positive for positive inputs. Like sigmoid, tanh saturates for large absolute inputs, so its derivative becomes small in those regions. Its zero-centered output can make it preferable to sigmoid in some hidden-layer settings, but it does not eliminate vanishing-gradient problems.

22. Q: What is a rectified linear unit, or ReLU?
A: Show answer
A rectified linear unit applies phi(z) = max(0, z). Negative pre-activations produce zero; positive pre-activations pass through unchanged. ReLU is computationally simple and does not saturate on its positive side, which can help gradient-based training in deep networks. Its outputs are nonnegative and often sparse because many units can be zero for a given example. ReLU is not bounded above and should not be interpreted as a probability. At exactly zero it is not differentiable, so implementations use a valid subgradient convention.

24. Q: Why can sigmoid or tanh saturation make training difficult?
A: Show answer
When a sigmoid input is very positive or very negative, its output is close to one or zero and its derivative is close to zero. Tanh behaves similarly near -1 and 1. During backpropagation, gradients are multiplied through successive derivatives, so repeated small derivatives can attenuate the signal reaching earlier layers. This is one contributor to vanishing gradients and slow learning in deep networks. Saturation is not always harmful—for example, bounded output probabilities can be useful—but it can be problematic when hidden units spend much of training in saturated regions.

26. Q: What is the dying-ReLU problem?
A: Show answer
A ReLU unit is inactive whenever its pre-activation is negative. If its inputs and weights keep the pre-activation negative for all training examples, its output remains zero and its local gradient is also zero. The unit may then receive no useful gradient to move back into an active region; this is commonly called a dying ReLU. Large updates, poor initialization, an unsuitable learning rate, or data distributions that place a unit mostly on the negative side can contribute. Remedies include checking activation statistics, reducing an excessive learning rate, adjusting initialization, or testing alternatives such as leaky ReLU.

27. Q: What does it mean for a ReLU network to be piecewise linear?
A: Show answer

29. Q: How does a two-input threshold neuron define a decision boundary?
A: Show answer
For two inputs, the neuron's boundary is the set of points satisfying w1 x1 + w2 x2 + b = 0. Points on one side produce a positive pre-activation and one threshold output; points on the other side produce a negative pre-activation and the alternative output. The boundary is a straight line in two dimensions and a hyperplane in higher dimensions. The weight vector is normal to that boundary, meaning it points perpendicular to it. Changing the weights changes the orientation and potentially the scale of the score; changing the bias translates the boundary.

30. Q: Why is the decision boundary perpendicular to the weight vector?
A: Show answer
The pre-activation without bias is the dot product w transpose x. A dot product is zero when the input vector is orthogonal to the weight vector. The points satisfying w transpose x + b = 0 form a hyperplane whose normal vector is w; every direction along the boundary has zero dot product with w. Therefore, the boundary is perpendicular to the weight vector. The sign of the dot product indicates which side of the boundary a point lies on when the bias is included in the affine score.

37. Q: How does a matrix multiplication calculate all neurons in a layer at once?
A: Show answer
Each output unit has its own column of weights. Multiplying the preceding layer's activation vector by the weight matrix forms the dot product with every column, producing all units' weighted sums in one operation. For a batch, matrix multiplication repeats this computation for many examples efficiently. The bias vector is broadcast across the batch, and the activation function is applied element-wise to the resulting matrix. This is algebraically equivalent to computing each neuron separately but exposes regular, parallelizable work to optimized numerical libraries and hardware.

19. Q: How does backpropagation train a multilayer neural network?
A: Show answer
Backpropagation uses two linked computational stages. In the forward pass, an input is passed through the network to produce an output and a loss is calculated by comparing that output with the target. In the backward pass, derivatives of the loss are propagated from the output layer toward earlier layers using the chain rule. Each weight receives a gradient that indicates how changing that weight would affect the loss. An optimizer then uses those gradients to update the weights. Backpropagation is the procedure for computing gradients; gradient descent or another optimizer is the procedure for applying them. This distinction prevents the common mistake of treating backpropagation and weight updating as identical operations.

21. Q: What is the vanishing-gradient problem, and why does depth make it more serious?
A: Show answer
During backpropagation, the chain rule multiplies derivatives from successive layers. The gradients for early layers may become extremely small, so their weights change very little even when the network’s output is wrong. Those early layers are important because they learn the features on which later representations depend. The problem is therefore not simply that a deep network has many parameters; it is that the learning signal can become too weak to train parameters far from the output. The effect can be especially severe in recurrent networks unfolded across long sequences.

27. Q: How does a spiking neuron differ from the artificial neuron commonly used in standard deep learning?
A: Show answer
A typical artificial neuron in a conventional feed-forward network computes an activation from its current inputs during a propagation step. This temporal behavior is one reason spiking systems are investigated for energy-efficient processing, although the actual advantage depends on circuit design, activity patterns, algorithms, and the application being evaluated.
