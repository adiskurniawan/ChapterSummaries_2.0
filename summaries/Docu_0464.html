1. Q: What is artificial intelligence, and what is the chapter's central way of framing it?
A: Show answer
Artificial intelligence (AI) is the field of building computational systems that perform tasks involving capabilities such as perception, language, reasoning, learning, planning, and action. The chapter introduces AI through the idea of reproducing selected functions associated with human intelligence, sometimes described as reverse engineering. That is a useful teaching metaphor, but it is not a complete definition: many AI methods are inspired by mathematics, statistics, control theory, optimization, or search rather than by copying the brain. A system can perform an intelligent task without possessing consciousness, human intentions, or general human understanding. The practical question is which capability is being automated, what objective is being pursued, and how performance will be evaluated.

- AI is a broad problem-solving field, not one algorithm or one model type.

3. Q: How should Mitchell's E, T, and P framework be used to decide whether a program is learning?
A: Show answer
The framework describes learning in relation to three elements: experience (E), task (T), and performance measure (P). Experience is the data, feedback, or interaction from which the system can improve. The task states what the program must do, such as classify images, predict a value, or choose a move. A system has not demonstrated learning merely because it receives more data; its performance on the defined task must improve under a meaningful evaluation. Teams should define the measure before training so that they do not select a metric after seeing which one makes the model look successful.

12. Q: How do robotics and control theory connect perception to physical action?

13. Q: What does the Turing Test assess, and what was Turing's original proposal?
A: Show answer
In his 1950 paper, Alan Turing reframed the question of whether machines can think as an imitation game. In a text-based arrangement, an interrogator communicates with hidden participants and tries to distinguish a machine from a human based on their responses. The test concerns whether the machine can produce conversation that is difficult for the interrogator to distinguish under the test conditions. It does not directly measure whether a system has consciousness, emotions, reliable knowledge, or safe decision-making ability. A system could imitate conversational behavior while making factual errors or acting unsafely in other contexts. The test is historically important, but it should not be treated as a universal certification of intelligence.

20. Q: What are a state, an action, and a state transition in a search problem?
A: Show answer
A state is a representation of the situation relevant to future decisions. In tic-tac-toe, a state can be the arrangement of X, O, and empty cells; an action places a sign in an available cell; and the transition produces the updated board. If illegal actions are included or legal actions are omitted, the search tree no longer represents the real problem correctly.

21. Q: What is a state space, and why can it grow so quickly?
A: Show answer
A state space is the set of states that can be reached under the rules of a problem. If each state has several possible actions, each action may generate further states, producing a branching search tree. The number of possible sequences can grow exponentially with search depth when the branching factor remains greater than one. Chess illustrates the difficulty: even a moderate number of possible moves at each turn produces an enormous number of future sequences. A small board game can also have many move sequences, although different sequences may lead to the same board position. Search therefore needs methods to avoid unnecessary exploration, use prior knowledge, or stop at a manageable depth.
Study instruction:
- For a toy problem with branching factor three, calculate the number of nodes at successive depths and explain why exhaustive search becomes expensive.
Key point:
- Branching factor and depth jointly determine search growth.
- The number of move sequences can exceed the number of distinct states.

22. Q: How does Breadth-First Search explore a tree or graph?
A: Show answer
Breadth-First Search (BFS) begins at a start node and explores nodes in increasing order of depth. It visits the start node, then its immediate successors, then the next layer, continuing until it finds a goal or exhausts the reachable space. A FIFO queue supports this order because the earliest discovered node is expanded first. In an unweighted graph, BFS can find a path with the fewest edges when it records visited nodes and predecessor information correctly. Its main limitation is memory: it may need to retain a large frontier while exploring broad levels. The chapter's tree example demonstrates the order of expansion; a graph implementation also needs protection against revisiting nodes through cycles or multiple paths.
Study instruction:
- Trace BFS on a small graph, recording the queue, visited set, and predecessor of each newly discovered node.
Key point:
- BFS explores level by level using a first-in, first-out frontier.
- It finds a minimum-edge path in an unweighted graph when implemented as graph search.

23. Q: How does Depth-First Search differ in the order in which it explores states?
A: Show answer
Depth-First Search (DFS) follows one branch as far as possible before backtracking to explore another branch. A stack, either explicit or represented by recursive calls, supports this behavior. DFS can use less frontier memory than BFS on some tree structures, but it may spend a long time following a deep or unproductive branch. In a graph, it still needs a visited set or equivalent cycle handling to avoid repeated exploration. DFS does not generally guarantee the shortest path, and in an infinite or very deep search space it may fail to reach a nearby goal if it follows an unbounded branch. Its usefulness depends on the structure of the search space and the required result.
Study instruction:
- Run DFS on the same graph used for BFS and compare the expansion order, memory use, and path found.
Key point:
- DFS explores deeply before backtracking, commonly using a stack.
- It is not a general shortest-path method and needs cycle handling on graphs.

24. Q: When should BFS be preferred over DFS, and when might DFS be more suitable?
A: Show answer
BFS is appropriate when the goal is to find a path with the fewest edges in an unweighted graph or when solutions are expected near the root and memory is sufficient. DFS can be useful when memory is constrained, when the search is naturally recursive, or when the objective is to explore a branch deeply rather than find the shortest path. Neither is automatically best for every problem. A search over a large, wide tree may make BFS memory-intensive, while a search with long or cyclic branches may make naive DFS inefficient. The choice should be based on the objective, branching pattern, depth, edge costs, and resource limits rather than on a general belief that one algorithm is more intelligent.

25. Q: Why must graph search usually track visited states when tree search may not?
A: Show answer
A tree has a unique path from its root to each node, while a graph may contain cycles and multiple paths to the same state. If a graph-search algorithm does not track visited or best-known states, it may revisit the same node repeatedly or loop forever. A visited set can prevent repeated expansion, while a distance map can record the best path cost found so far. However, simply marking a node visited on first discovery is not sufficient for every weighted-search algorithm: a later path may be cheaper, so the implementation must follow the algorithm's update and reopening rules. State identity must also be defined carefully so that genuinely equivalent states are recognized without merging states that differ in a decision-relevant way.
Study instruction:
- Add a cycle and two alternative paths to a graph, then test how visited-state and best-cost records change the search.
Key point:
- Graphs can revisit the same state through different routes.
- The correct duplicate-handling rule depends on the search algorithm and edge costs.

26. Q: Why is a deque usually preferable to a Python list with pop(0) for a BFS queue?
A: Show answer
The chapter's illustrative BFS code removes the first element of a list with pop(0). This is easy to understand, but Python lists must shift the remaining elements when the first item is removed, so repeated front removals can become expensive. collections.deque is designed for efficient appends and pops at either end and is therefore a better queue structure for practical BFS implementations. A typical pattern is to append newly discovered nodes on the right and remove the next node from the left. The choice of data structure does not change BFS's logical order, but it can materially affect execution time on large searches. This is an example of how implementation details influence algorithm performance.
Study instruction:
- Rewrite a list-based BFS queue using collections.deque and compare the operations used to add and remove nodes.
Key point:
- A FIFO queue is part of BFS's logic, but the queue implementation affects efficiency.
- deque avoids the repeated shifting associated with list pop(0).

30. Q: How do immediate-win and immediate-block rules improve a tic-tac-toe agent?
A: Show answer
An immediate-win rule checks whether any legal move completes a winning line for the agent and selects that move if one exists. If no winning move is available, an immediate-block rule checks whether the opponent could win on the next turn and occupies the threatened cell. These rules encode tactical priorities that a random agent ignores. They are useful because they prevent obvious mistakes with little computation. However, they do not guarantee optimal play: a position may contain a fork, multiple threats, or a longer tactical sequence that cannot be handled by checking only one move ahead. The rules are best understood as a simple policy improvement and a stepping stone toward systematic search.

Key point:
- Tactical rules can eliminate obvious errors quickly.

31. Q: How do symmetry reduction and transposition detection reduce a game search space?

42. Q: What is the Minimax algorithm, and why does it model two-player adversarial games?
A: Show answer
Minimax evaluates a game tree by assuming that both players choose moves that serve their own objectives. At a minimizing node, the opponent selects the successor with the lowest utility from that same perspective. This is suitable for deterministic, alternating, two-player, zero-sum games when both players are modeled as choosing optimally. If players have different objectives, random outcomes, hidden information, or non-zero-sum incentives, the model must be extended rather than applying ordinary Minimax without qualification.

26. Q: How does majority voting determine a KNN prediction?
A: Show answer
After the k closest training observations have been identified, the classifier counts the class labels among those neighbours. 29. Q: What is Manhattan distance, and how does it differ from Euclidean distance?
A: Show answer

7. Q: How is entropy calculated for a categorical target distribution?
A: Show answer
For class probabilities p1 through pk, entropy is H = -Σ pi log2(pi). The probabilities must be non-negative and sum to one. A class with probability zero contributes zero to the sum by convention, because the limiting value of p log2(p) is zero as p approaches zero. Entropy is measured in bits when the logarithm is base two. For two classes, entropy is zero when one class has probability one and reaches one bit when the classes each have probability one-half. For more than two classes, the maximum is log2(k) when all k classes are equally likely. Always normalize counts into probabilities before applying the formula.

9. Q: What is information gain, and how does it guide the selection of a decision-tree split?
A: Show answer
Information gain is the reduction in target-label entropy produced by a candidate split. First calculate the entropy of the parent node. Then partition the observations, calculate the target entropy in each child, and take the weighted average of those child entropies using each child's share of observations. Information gain equals parent entropy minus that weighted child entropy. A larger positive gain indicates a greater reduction in uncertainty for that split. Weighting matters because a child containing one record should not count as much as a child containing most of the dataset. A split that isolates a tiny pure group while leaving a large mixed group may offer only modest overall gain.

40. Q: What is a recurrent neural network, and what makes its input sequential?
A: Show answer
A recurrent neural network is designed for data in which order matters, such as words in a sentence or measurements recorded over time. At each time step, the network processes the current input and a hidden state that carries information from earlier steps. This allows the current output to depend on both the current observation and a representation of prior context. The same recurrent computation is applied across the sequence. The chapter identifies speech recognition, chatbots, translation, and time-series prediction as applications. RNNs require careful sequence construction, padding or masking where necessary, and evaluation that respects temporal order so that future information does not leak into past predictions.

41. Q: What is the hidden state in a basic RNN?
A: Show answer
The hidden state is a vector that carries information from previous time steps into the current recurrent computation. At time t, the network combines the current input xₜ with the previous hidden state hₜ₋₁ to calculate a new hidden state hₜ and, where configured, an output. This creates a form of learned sequence memory. The hidden state is not a perfect record of every prior input; it is a compressed representation learned through training. Its quality depends on the architecture, sequence length, training data, and optimization. The chapter's diagram emphasizes that the same recurrent network is unfolded across time for illustration, rather than representing a separate independent network at every time step.

42. Q: What are the limitations of a simple RNN on long sequences?
A: Show answer
A basic RNN repeatedly transforms its hidden state as it processes a sequence. During training, gradients must propagate through many time steps, which can lead to vanishing or exploding gradients. As a result, a simple RNN may struggle to learn dependencies that span long intervals. The chapter explains the practical concern that a final prediction can be influenced by every previous input, even when much of that history is not relevant. Gated architectures such as GRU and LSTM introduce mechanisms that regulate how information is retained or updated. They do not eliminate every training difficulty, but they are designed to improve the handling of longer-term dependencies compared with a basic recurrent cell.

43. Q: How does a Gated Recurrent Unit improve on a simple RNN?
A: Show answer
A GRU adds gates that regulate how information from the previous state and the current candidate state are combined. The chapter emphasizes an update gate, commonly using a sigmoid activation, that controls how much new candidate information should be incorporated. The gates help the model retain or replace information more selectively than a basic RNN. 44. Q: How does an LSTM manage longer-term information in a sequence?
A: Show answer
Long Short-Term Memory networks use a cell state and gates to regulate information over time. The forget gate controls which existing information should be retained or removed; the input gate controls how new candidate information is written into the cell state; and the output gate controls what information is exposed as the hidden output. This structure gives the network a more explicit mechanism for preserving selected information across time steps. The chapter describes LSTM as a popular recurrent cell and contrasts it with the simpler GRU. LSTM is not guaranteed to outperform every alternative; model choice depends on sequence length, data volume, task, computational budget, and validation results.

48. Q: Why are interpretability, bias, and fairness important challenges for deep learning?
A: Show answer
Deep networks can contain many layers and parameters, making it difficult to explain why a particular prediction was produced. If training data reflect historical inequities, incomplete coverage, or measurement errors, a model may reproduce or amplify those patterns. In high-impact uses such as credit decisions, health, employment, or public services, unexplained errors can cause serious harm. Practitioners should examine data representativeness, performance across relevant subgroups, calibration, error patterns, and the limits of explanation methods. A model's apparent accuracy does not establish that its decisions are fair or justified. Governance should include documentation, human review, avenues for contesting decisions, privacy and security controls, and ongoing monitoring of real-world outcomes.
