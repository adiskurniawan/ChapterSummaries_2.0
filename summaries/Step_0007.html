LOCAL EBOOK WORKFLOW — PROJECT OVERVIEW
🎯 Workflow Objective

Automate the quality-control and archiving process for generated ebook chapter summaries.

Only source/result pairs that pass the structural comparison rules are treated as qualified for:

• Source-folder relocation.
• Result-folder ZIP archiving.
• Subsequent result-folder cleanup after successful ZIP verification.
• Verified backup of eligible files from the Done folder.

📚 Ebooks_txt/ Folder

Contains the original ebook source folders and chapter documents.

• Ebook folders – Contain the original ebook chapters.
• Chapter files – Stored in .txt format and used as the source documents for comparison.
• Chapter numbering – Provides the reference chapter identifiers against which generated results are checked.

Qualified source relocation:

Source ebook folders that pass the comparison are moved to:

E:\EBOOKS\EBOOKS_28\Ebooks_txt_2027
🗂️ ChatGPT Library/ Folder

Contains the ebook mapping file:

• Chapter Summaries Q&A Books.txt – Maps source ebook folder identifiers to their corresponding generated result folders.
• Mapping identifiers – Identify the corresponding Docu_#### result folders.
• Duplicate mapping identifiers – Excluded from matching.

The mapping file is used to identify the source ebook folder and corresponding generated result folder for each mapped book.
📦 ChatGPT Library Results/ Folder

Contains the generated ebook chapter results and operational workflow files.

• Docu_####/ – Contains generated chapter result documents in .md or .txt format.
• Done/ – Contains files that are processed for verified backup to Dropbox.
• Duplicate_MD_Cleanup_Log.txt – Records duplicate cleanup, comparison outcomes, folder relocation, ZIP archiving, Done-folder backup, and failures.
• Comparison_Result.md – Contains qualified books and chapter-count mismatch information.

Result-folder cleanup:

Qualified Docu_#### folders are moved to the Windows Recycle Bin only after their corresponding ZIP archives have been successfully verified.
🧹 Stage 1 — Duplicate Markdown Cleanup

Scans each immediate result subfolder matching Docu_####.

• Identifies Markdown files representing the same chapter.
• Keeps the largest file.
• If file sizes are equal, keeps the newest file based on modification time.
• Moves the remaining duplicate files to the Windows Recycle Bin.

Objective: Remove unnecessary duplicate Markdown chapter files before comparison.
📋 Stage 2 — Load Ebook Mapping

Reads:

Chapter Summaries Q&A Books.txt

• Extracts the source ebook folder identifier.
• Identifies the corresponding generated result-folder identifier.
• Excludes duplicate mapping identifiers from matching.

Objective: Establish the mapping between original ebook folders and generated result folders.
🔍 Stage 3 — Match Source and Result Folders

For each mapped ebook, identifies:

• Source folder – Matching ebook folder inside Ebooks_txt/.
• Result folder – Corresponding Docu_#### folder inside ChatGPT Library Results/.

Both folders must exist for the ebook to qualify.

Example:
• Result folder identifier: 0470
• Result folder: Docu_0470
• Source folder: Corresponding original ebook folder under Ebooks_txt/
📄 Stage 4 — Identify Chapter Documents

Identifies the relevant documents to compare in each matched folder.

• Source files: .txt
• Result files: .md or .txt

Only recognized and relevant chapter documents are included in the comparison.

Files must be readable and recognized by the workflow to be eligible for qualification.
🔢 Stage 5 — Normalize Chapter Identifiers

Extracts chapter numbers from filenames.

• Chapter numbers are used as the primary matching identifiers.
• Descriptive chapter titles are ignored when determining chapter identity.
• Timestamps are ignored when determining chapter identity.

Objective: Identify corresponding chapters without requiring identical filenames or descriptive titles.
🔁 Stage 6 — Check Duplicate Chapter Identifiers

Checks whether each chapter number occurs more than once within either document set.

• Source chapter identifiers must be unique.
• Result chapter identifiers must be unique.

A source or result set containing duplicate chapter numbers is not eligible for qualification.

Important: Equal source and result file counts do not eliminate the possibility of duplicate chapter identifiers.
⚖️ Stage 7 — Compare Chapter Counts and Coverage

Performs two separate checks.

Chapter count comparison:
• Source and result sets must contain the same number of recognized chapter documents.

Chapter coverage comparison:
• Source and result sets must contain exactly the same set of unique chapter identifiers.

Example:
• Source chapters: 1, 2, 3, 4, 5.
• Result chapters: 1, 2, 3, 4, 5.
• Source count: 5.
• Result count: 5.
• Counts match.
• Chapter-number sets match exactly.

Equal document counts alone are insufficient. Both the counts and chapter-number sets must match.
✅ Stage 8 — Determine Ebook Qualification

An ebook qualifies only when all the following conditions are satisfied:

1. Source ebook folder exists.
2. Corresponding Docu_#### result folder exists.
3. Relevant chapter files are readable and recognized.
4. Source chapter identifiers are unique.
5. Result chapter identifiers are unique.
6. Source and result document counts are equal.
7. Source and result chapter-number sets are identical.

All conditions must be satisfied for an ebook to qualify.

Objective: Establish exact structural correspondence between original ebook chapters and generated result chapters.
📊 Stage 9 — Classify Comparison Results

Each ebook is classified according to its comparison outcome.

• Qualified – All qualification conditions are satisfied.
• Chapter-count mismatch – Source and result document counts differ.
• Other not-qualified / In progress – Includes books that fail another qualification condition or remain in progress.

The comparison report records the applicable outcome and relevant information.
📑 Stage 10 — Generate Comparison Report

Generates:

Comparison_Result.md

The report contains:

• Qualified Results – Books that satisfy all qualification conditions.
• Chapter-count Mismatches – Books with different source and result chapter counts.
• Other Not-Qualified Results – Books that fail other qualification conditions or remain in progress.

Detailed processing activities and failure reasons are recorded in the consolidated log.
📂 Stage 11 — Move Qualified Source Folders

Moves qualified source ebook folders to:

E:\EBOOKS\EBOOKS_28\Ebooks_txt_2027

• Only qualified source folders are moved.
• If a destination folder already exists, the workflow uses a temporary backup/restore approach when replacing it.

Objective: Relocate successfully compared source ebooks to the designated destination.

Important: Review existing destination contents before execution if they contain unique data.
🗜️ Stage 12 — ZIP Qualified Result Folders

Uses the qualified result list generated by the comparison stage.

• No manual folder-number prompt is required.
• Creates ZIP archives in the Dropbox tables directory.
• Preserves nested directories.
• Preserves empty directories.
• Excludes the top-level Docu_#### folder itself from the archive paths.

ZIP destination:

tables

Objective: Archive only qualified generated ebook results.
🔐 Stage 13 — Verify ZIP Archives and Recycle Result Folders

Creates each ZIP archive through a temporary file.

Verification procedure:

1. Create the ZIP archive as a temporary file.
2. Test the archive for integrity.
3. Atomically replace the destination ZIP only after successful verification.
4. Move the corresponding Docu_#### result folder to the Windows Recycle Bin only after its ZIP has passed verification.

Failure handling:

• If ZIP creation fails, retain the original result folder.
• If ZIP verification fails, retain the original result folder.
• Do not recycle a result folder before successful ZIP verification.

Objective: Prevent loss of generated ebook results before a verified archive is available.
☁️ Stage 14 — Back Up the Done Folder

Copies files from:

ChatGPT Library Results\Done

To the Dropbox tables directory while preserving relative paths.

Backup verification procedure:

1. Compare existing backups using SHA-256.
2. Copy files through a temporary file.
3. Verify the copied file hash.
4. Delete a source file only when an identical verified backup exists or a new copy has been successfully verified.
5. Retain files when a conflict or failure occurs.

Objective: Ensure that eligible Done-folder files have verified backups before source deletion.

Important: Matching SHA-256 hashes provide strong confirmation that the source and backup files are byte-for-byte identical.
📝 Stage 15 — Write the Consolidated Log

Generates or updates:

Duplicate_MD_Cleanup_Log.txt

Records the complete workflow execution, including:

• Duplicate Markdown cleanup statistics.
• Comparison outcomes.
• Source-folder relocation results.
• ZIP creation and verification results.
• Done-folder backup outcomes.
• Processing failures and errors.

Objective: Maintain a consolidated operational record of the entire workflow.

⚠️ Safety Checks and Limitations

Structural qualification only
Matching chapter numbers and counts do not prove that generated summaries are accurate or complete.

ZIP verification

SHA-256 verification

Recycle Bin behavior
Recycled folders and duplicate files are generally recoverable through Windows Recycle Bin, subject to Windows settings and subsequent cleanup.

Dropbox synchronization
A successful local copy to the Dropbox-synced directory does not by itself guarantee that cloud synchronization has finished.

Destination replacement
Existing qualified-source destination folders may be replaced using the script's temporary backup and restoration logic. Review destination contents before execution if they contain unique data.

Python is a general-purpose programming language used to automate tasks, process data, manage files and folders, perform comparisons, and generate reports.

In this project, Python acts as the local automation engine. Instead of manually opening hundreds of ebook folders and comparing chapter documents, Python executes the programmed operations automatically.

Main benefits:
• Automates repetitive tasks.
• Processes multiple files and folders.
• Applies consistent comparison rules.
• Reduces manual work.
• Generates repeatable reports.
• Helps identify errors and inconsistencies.
• Performs controlled file relocation, archiving, and backup operations.
2. INTRODUCTION TO CHATGPT AND PYTHON

ChatGPT can assist with developing, explaining, reviewing, debugging, testing, and improving Python scripts.

ChatGPT is not the execution engine in this local workflow. The actual Python script runs on the Windows computer using the installed Python interpreter.

Typical development process:
1. Explain the task and expected outcome to ChatGPT.
2. ChatGPT develops or revises the Python code.
3. Save the code as a .py file.
4. Run the script using Python on Windows.
5. Review the generated files, reports, and execution logs.
6. Provide errors or unexpected results to ChatGPT for investigation.
7. Revise and test the script again.

Important distinction: ChatGPT assists with script development and troubleshooting. The local Python environment executes the script and performs the actual filesystem operations.
3. WHAT IS A PYTHON SCRIPT?

A Python script is a text file containing instructions written in the Python programming language. It normally uses the .py extension.

Project example:

7. ABSOLUTE PATH VS. RELATIVE PATH

Absolute path: Specifies the complete location of a file or folder.

Example:

Relative path: Specifies a location relative to a defined working directory or another reference path.

Example:
Ebook 1\\Chapter_01.txt

Differences:
• Absolute paths identify a specific filesystem location.
• Relative paths depend on the reference directory.
• Absolute paths are useful for fixed project locations.
• Relative paths can make projects easier to relocate when their directory structures are preserved.

Important: Changing the current working directory can affect how relative paths are resolved.

9. UNDERSTANDING PYTHON FOLDER SCANNING

D:\\Box Sync\\ChatGPT Library Results

Two scanning methods:

• Immediate folder scanning – Examines direct subfolders only.
• Recursive folder scanning – Examines subfolders and their descendants.

Project application:

10. FILE READING AND WRITING

Python can read existing files and write new files or updated content.

Reading:
Retrieves existing file contents for processing or analysis.

Writing:
Creates a new file or writes content to an existing file.

Appending:
Adds new information to the end of an existing file without replacing its previous contents.

Examples in this project:
• Reading Chapter Summaries Q&A Books.txt.
• Inspecting source chapter filenames.
• Reading result folder contents.
• Generating Comparison_Result.md.
• Recording processing activity in Duplicate_MD_Cleanup_Log.txt.

Important: Writing to an existing file can overwrite its previous contents, depending on the file-opening mode. Appending preserves existing contents while adding new information.
11. FILE COPYING, MOVING, AND DELETING

These operations have different effects on files and folders.

Copy: Creates another copy while retaining the original.

Move: Changes the location of a file or folder. After a successful move, the original location no longer contains that item.

Delete: Removes a file or folder from its normal filesystem location.

Recycle Bin: Provides a recovery location for supported Windows deletion operations.

Applications in this project:
• Duplicate Markdown files are moved to the Windows Recycle Bin using send2trash.
• Qualified source ebook folders are moved to the designated E: destination.
• Qualified result folders are moved to the Recycle Bin after successful ZIP verification.
• Done-folder files are copied to Dropbox and deleted from their source locations only after successful backup verification.

Important: Moving, copying, and recycling are different operations. Their failure handling and verification requirements must be considered separately.
12. UNDERSTANDING FILE SIZE AND MODIFICATION DATE

Python can retrieve file metadata without comparing the complete contents of documents.

File size: The amount of storage occupied by a file, usually measured in bytes.

Modification date and time: Records when a file was last modified according to filesystem metadata.

These properties are used by the duplicate Markdown cleanup process:

1. Identify files representing the same chapter.
2. Compare their file sizes.
3. Retain the largest file.
4. If sizes are equal, compare modification dates.
5. Retain the newest file.
6. Move the remaining duplicates to the Recycle Bin.

Limitation: A larger file or newer modification date does not necessarily mean that a document contains better or more accurate information. The selection is based on the configured retention rules.
13. WINDOWS RECYCLE BIN VS. PERMANENT DELETION

Windows supports different ways of removing files and folders.

Move to Recycle Bin:
Moves an item into the Recycle Bin, where it can generally be restored before the bin is emptied.

Permanent deletion:
Removes an item without sending it through the normal Recycle Bin recovery process.

Project implementation:

Important considerations:
• Recycle Bin operations are generally recoverable, subject to Windows settings.

• Never assume that a deletion or recycling operation succeeded without checking its result.

24. IMPORTANT DISTINCTION — CODE TESTING VS. ACTUAL EXECUTION

Passing a syntax check means Python can parse the script without detecting a syntax error. It does not prove that every operation will work against the actual files.

Syntax testing: Checks whether the code is syntactically valid.

Unit testing: Tests individual functions using controlled inputs.

Synthetic testing: Tests selected workflow scenarios using artificial example data.

Integration testing: Checks whether different parts of the workflow operate together correctly.

Actual execution: Runs the script against the real source and result folders.

Result verification: Checks the actual files, folder locations, ZIP archives, backups, reports, and logs produced by execution.

Important: These are different levels of testing and must not be treated as interchangeable. A successful syntax check does not establish that actual file operations are safe or successful.

27. PRACTICAL EXAMPLE — HOW THE EBOOK WORKFLOW OPERATES

Suppose the original source folder contains:

• Chapter_01.txt
• Chapter_02.txt
• Chapter_03.txt

The generated result folder contains:

• Chapter 01 - Introduction.md
• Chapter 02 - Background.md
• Chapter 02 - Background Copy.md
• Chapter 03 - Conclusion.md

Step 1 — Duplicate cleanup:

The cleanup process identifies two result files representing chapter 2. It retains the largest file or, if their sizes are equal, the newest file. The remaining duplicate is moved to the Recycle Bin.

Step 2 — Chapter comparison:

The comparison process checks the remaining source and result chapters:

• Source: 1, 2, 3.
• Result: 1, 2, 3.

Step 3 — Qualification:

If all other qualification conditions are also satisfied, the ebook qualifies.

Step 4 — Source relocation:

The qualified source folder is moved to the configured E: destination.

Step 5 — Result archiving:

The qualified result folder is compressed into a ZIP archive in the Dropbox tables directory.

Step 6 — ZIP verification:

The archive is tested for integrity. Only after successful verification is the original result folder moved to the Recycle Bin.

Step 7 — Done-folder backup:

Eligible Done-folder files are copied to Dropbox and verified using SHA-256 before their source copies are deleted.

This example illustrates how duplicate cleanup, comparison, qualification, relocation, archiving, and backup form a sequential automation workflow.
