📚 Ebooks_txt/ Folder

Contains the original ebook source folders and chapter documents.

🗂️ ChatGPT Library/ Folder

Contains the ebook mapping file:

• Chapter Summaries Q&A Books.txt – Maps each four-digit ebook ID to its corresponding ebook title.

• Ebook title – Used to locate the matching source ebook folder.
📦 ChatGPT Library Results/ Folder

Stores the generated ebook chapter results and the reports produced by the Python workflow.

• Docu_####/ – Contains generated chapter result files in .md or .txt format.

• Comparison_Result.md – Contains the ebook comparison results and qualification status.
🧹 Stage 1 — Duplicate Markdown Cleanup

Scans immediate result subfolders matching Docu_####.

• Identifies Markdown files representing the same chapter number.
• Keeps the largest file.
• If file sizes are equal, keeps the newest file based on modification time.
• Moves the remaining duplicate files to the Windows Recycle Bin.
• Records cleanup activity and failures in Duplicate_MD_Cleanup_Log.txt.

Objective: Remove unnecessary duplicate chapter files before comparison.
📋 Stage 2 — Load Ebook Mapping

Reads Chapter Summaries Q&A Books.txt.

Expected format:
0470: Mastermind - How to Think Like Sherlock Holmes
0479: Level Up - Rob Dial
0498: Improve Your Memory - Mark Channon

Extracts the four-digit ebook ID and corresponding title for folder matching.
🔍 Stage 3 — Match Source and Result Folders

For each mapped ebook, identifies:

• Source folder – Matching ebook folder inside Ebooks_txt/.
• Result folder – Corresponding Docu_#### folder inside ChatGPT Library Results/.

Source folder matching uses normalized text comparison to accommodate differences in punctuation and formatting.

Example:
• Ebook ID: 0470
• Ebook title: Mastermind - How to Think Like Sherlock Holmes
• Result folder: Docu_0470
📄 Stage 4 — Identify Chapter Documents

Identifies the documents to compare in each matched folder.

• Source files: .txt
• Result files: .md or .txt

Extracts chapter numbers from recognized filenames. The configured logic can also check parent folder names when applicable.

Files without recognizable chapter numbers cannot be treated as valid chapter matches.
🔢 Stage 5 — Normalize Chapter Numbers

Uses chapter numbers as the primary matching keys rather than requiring identical filenames or descriptive titles.

Example:
• Chapter_05.txt
• Chapter 05 - Introduction.md
• Chapter-5_20261120.md

All represent chapter 5.

Chapter numbers are standardized so that 05 and 5 are treated as the same identifier.
🔁 Stage 6 — Check Duplicate Chapters

Checks whether each chapter number occurs exactly once on each side.

• Source chapter numbers must not contain duplicates.
• Result chapter numbers must not contain duplicates.

For example, two result files representing chapter 5 constitute a duplicate chapter identifier, even if the total source and result file counts are equal.
⚖️ Stage 7 — Compare File Counts and Chapter Coverage

Performs two separate checks:

File count comparison:
• Source: 12 files.
• Result: 12 files.
• Counts match.

Chapter-number comparison:
• Source: 1, 2, 3, 4, 5.
• Result: 1, 2, 3, 4, 5.
• Chapter numbers match exactly.

Equal file counts alone are insufficient. Both the counts and chapter-number sets must match.
✅ Stage 8 — Determine Ebook Qualification

An ebook qualifies only when all the following conditions are satisfied:

1. Source ebook folder exists and is matched reliably.
2. Corresponding Docu_#### result folder exists.
3. Relevant chapter files are readable and identifiable.
4. Every source chapter number occurs exactly once.
5. Every result chapter number occurs exactly once.
6. Source and result file counts are equal.
7. Source and result chapter-number sets are identical.

All conditions must be satisfied for an ebook to qualify.
📊 Stage 9 — Classify Comparison Results

Each ebook is classified according to its comparison outcome.

• Qualified – All qualification conditions are satisfied.
• Count mismatch – Source and result document counts differ.
• Other not-qualified – Includes missing or ambiguous source folders, missing result folders, no relevant documents, unreadable files, or unrecognized chapter filenames.

The report records the applicable reason and relevant counts.
📑 Stage 10 — Generate Comparison Report

Generates:
D:\Box Sync\ChatGPT Library Results\Comparison_Result.md

The Markdown report contains:

• Summary Counts – Overall qualification and mismatch totals.
• Qualified Ebooks – Ebook IDs, titles, and matching document counts.
• Count Mismatches – Ebook IDs and source/result file counts.
• Other Not-Qualified Ebooks – Recorded reasons and relevant counts.
• Comparison Rules – Chapter identification and qualification requirements.
📏 Comparison Rules

• Source folder – Must exist and be matched reliably.
• Result folder – Must exist.
• Source format – .txt.
• Result formats – .md or .txt.
• Chapter identification – Chapter number only.
• Duplicate chapter numbers – Not allowed.
• File counts – Must be equal.
• Chapter-number sets – Must match exactly.
• Readability and identification – Required for relevant documents.

Python, ChatGPT & File/Folder Operations — Practical User Guide
1. INTRODUCTION TO PYTHON

Python is a programming language used to automate tasks, process files, organize folders, compare data, and generate reports.

In this project, Python acts as the automation engine. Instead of manually opening hundreds of ebook folders and comparing chapter files, the script performs the repetitive operations automatically.

Main benefits:
• Automates repetitive tasks.
• Processes multiple folders and files.
• Applies consistent comparison rules.
• Reduces manual checking.
• Generates repeatable reports.
• Makes it easier to identify errors and inconsistencies.
2. INTRODUCTION TO CHATGPT AND PYTHON

ChatGPT can assist with developing, explaining, reviewing, debugging, and improving Python scripts.

ChatGPT is not the Python execution engine in this local workflow. The actual Python script runs on the Windows computer using the installed Python interpreter.

Typical development process:
1. Explain the task and expected outcome to ChatGPT.
2. ChatGPT develops or revises the Python code.
3. Save the code as a .py file.
4. Run the script using Python on Windows.
5. Review the generated output and execution logs.
6. Provide errors or unexpected results to ChatGPT for investigation.
7. Revise and test the script again.

Important distinction: ChatGPT helps create and improve the automation. The local Python environment executes the script and performs the actual file operations.
3. WHAT IS A PYTHON SCRIPT?

A Python script is a text file containing Python instructions. It normally uses the .py extension.

Example:
Combined_Ebook_Cleanup_and_Comparison.py

The script contains instructions that tell Python:
• Which folders to access.
• Which files to search for.
• How to identify duplicate files.
• How to compare chapter numbers.
• What conditions determine qualification.
• Where to save reports.

When executed, Python reads the instructions and performs the specified operations in sequence.
4. PYTHON INTERPRETER

The Python interpreter is the software that executes Python scripts.

For example, when the following command is executed in Command Prompt:

python Combined_Ebook_Cleanup_and_Comparison.py

Windows invokes the Python interpreter, which reads and executes the script.

Key distinction:
• .py file – Contains the program instructions.
• Python interpreter – Executes those instructions.
• Command Prompt – Provides an interface for entering execution commands.
• Windows – Provides access to the local filesystem and operating system functions.

Python can interact with the Windows filesystem through built-in modules and operating system functions.

Common operations include:

• Read file contents.
• Write new files.
• Rename files.
• Copy files.

Absolute path: Specifies the complete location of a file or folder.

Example:

Relative path: Specifies a location relative to a defined working directory or another reference path.

Example:
Ebook 1\Chapter_01.txt

Absolute paths are useful when the script must access specific locations on the computer. Relative paths can make a project easier to move when its folder structure is preserved.

10. FILE READING AND WRITING

Python can read existing files and write new files or updated content.

Reading:
Retrieves existing file contents for processing or analysis.

Writing:
Creates a new file or writes content to an existing file.

Appending:
Adds new information to the end of an existing file without replacing its existing contents.

Examples in this project:
• Reading Chapter Summaries Q&A Books.txt.
• Inspecting source chapter filenames.
• Reading result folder contents.
• Writing Comparison_Result.md.
• Recording execution details in Duplicate_MD_Cleanup_Log.txt.

Important: Writing to an existing file can overwrite its previous contents, depending on the file-opening mode used by the script.
11. FILE COPYING, MOVING, AND DELETING

These operations have different effects on files.

Copy: Creates another copy of a file while retaining the original.

Move: Changes the file's location. The file is no longer present in its original location after a successful move.

Delete: Removes a file from its normal filesystem location. Depending on the deletion method, it may be permanently deleted or sent to the Recycle Bin.

Recycle Bin: Provides a recovery location for files moved there through supported Windows deletion operations.

In this project, duplicate Markdown files are moved to the Windows Recycle Bin using the Windows file operation mechanism.
12. UNDERSTANDING FILE SIZE AND MODIFICATION DATE

Python can retrieve file metadata without needing to compare the full document contents.

File size: The amount of storage occupied by a file, usually measured in bytes.

Modification date and time: Records when a file was last modified according to the filesystem metadata.

These properties are used by the duplicate cleanup process:

1. Compare the sizes of duplicate chapter files.
2. Retain the largest file.
3. If sizes are equal, compare modification dates.
4. Retain the newest file.

Limitation: A larger file or newer modification date does not necessarily mean that the document contains better or more accurate information.
13. WINDOWS RECYCLE BIN VS. PERMANENT DELETION

Windows supports different ways of removing files.

Move to Recycle Bin:
Moves a file into the Recycle Bin, where it can generally be restored before the bin is emptied.

Permanent deletion:
Removes a file without sending it to the normal Recycle Bin recovery process.

The duplicate cleanup script uses the Windows SHFileOperationW mechanism to move duplicate files to the Recycle Bin.

Important: The cleanup log should be checked to confirm which files were successfully moved and whether any operations failed.
14. UNDERSTANDING FILE COMPARISON

File comparison means checking two sets of files against defined criteria.

In this project, the two sets are:

Source documents: Original ebook chapter files in .txt format.

Result documents: Generated chapter files in .md or .txt format.

The comparison focuses on:
• Number of files.
• Identifiable chapter numbers.
• Duplicate chapter numbers.
• Missing chapter numbers.
• Exact chapter-number coverage.

This is a structural comparison, not a comparison of the actual chapter contents.
