LOCAL EBOOK WORKFLOW — PROJECT OVERVIEW
🎯 Workflow Objective

Automate the mapping synchronization, quality-control, and archiving process for generated ebook chapter summaries.

The workflow automatically synchronizes the book mapping file against the actual existing Docu_#### result folders before performing ebook comparison.

Only book titles with corresponding existing result folders are retained in the active mapping file.

• Source-folder relocation.
• Result-folder ZIP archiving.
• Subsequent result-folder cleanup after successful ZIP verification.
• Verified backup of eligible files from the Done folder.

🔄 Stage 0 — Automatic Mapping Audit and Synchronization

Runs automatically before the existing ebook cleanup and comparison workflow.

Source file:
D:\Box Sync\ChatGPT Library\Chapter Summaries Q&A Books.txt

Target folder:
D:\Box Sync\ChatGPT Library Results\

Procedure:

1. Read the complete contents of Chapter Summaries Q&A Books.txt.
2. Extract the original four-digit book identifiers and corresponding titles.
3. Inspect the actual immediate subfolders inside ChatGPT Library Results/.
4. Identify existing folders matching the exact Docu_#### naming pattern.
5. Compare each source mapping identifier against the actual existing folder identifiers.
6. Retain only mappings whose corresponding Docu_#### folders exist.
7. Preserve the original book titles, identifiers, and relative ordering.
8. Preserve a backup of the original mapping before modifying the active file.
9. Update Chapter Summaries Q&A Books.txt with the matched mappings only.
10. Generate Folder_Mapping_Audit.txt containing the mapping and folder comparison results.

Step 1 — Matched Book Titles:

Contains only book-title mappings with corresponding existing Docu_#### folders.

Example:

Step 2 — Unmatched Docu Folders:

Lists actual existing Docu_#### folders whose identifiers do not appear in the matched source mapping.

Example:
• Docu_0450
• Docu_0471

These examples are illustrative only; actual results are determined from the live folder structure.

Mapping synchronization rules:

• Existing folder names are the source of truth for matching.
• Do not invent or assume folder names.
• Do not add titles for folders that cannot be matched to the source mapping.
• Do not retain titles without corresponding existing folders.
• Preserve original book titles exactly.
• Do not modify or delete any Docu_#### folders.
• Do not create, rename, or move folders.
• Exclude ambiguous duplicate mapping identifiers from matching.

Safety protections:

• Preserve the original mapping before modification.
• Do not overwrite the active mapping if source parsing or folder inspection fails.
• Do not overwrite the active mapping if there are zero valid matches.
• Use temporary-file replacement to prevent partially written mapping files.
• Record errors and audit results.
• An audit failure must not prevent the existing workflow from continuing, but the original mapping must remain unchanged when synchronization cannot be completed safely.

Objective: Ensure that Chapter Summaries Q&A Books.txt contains only mappings corresponding to actual existing result folders before ebook comparison begins.

Checks whether each chapter number occurs more than once within either document set.

• Source chapter identifiers must be unique.
• Result chapter identifiers must be unique.

A source or result set containing duplicate chapter numbers is not eligible for qualification.

Important: Equal source and result file counts do not eliminate the possibility of duplicate chapter identifiers.
⚖️ Stage 7 — Compare Chapter Counts and Coverage

Performs two separate checks.

Chapter count comparison:
• Source and result sets must contain the same number of recognized chapter documents.

Chapter coverage comparison:
• Source and result sets must contain exactly the same set of unique chapter identifiers.

Example:
• Source chapters: 1, 2, 3, 4, 5.
• Result chapters: 1, 2, 3, 4, 5.
• Source count: 5.
• Result count: 5.
• Counts match.
• Chapter-number sets match exactly.

Equal document counts alone are insufficient. Both the counts and chapter-number sets must match.

⚠️ Safety Checks and Limitations

Mapping synchronization
Only immediate directories matching Docu_#### are considered. Other folders, including Done, are ignored.

Original mapping protection
The original mapping must be backed up before modification. Failed or incomplete inspections must not produce an incomplete replacement mapping.

Title preservation
Retained titles must be copied from the original source file, not reconstructed from folder names.

Unmatched folders
Existing Docu_#### folders without corresponding source mapping entries are reported. The workflow must not invent book titles for them.

Mapping versus qualification
Having an existing result folder only establishes a valid mapping. It does not mean the ebook has passed chapter comparison.

Archived result folders
Result folders moved to the Recycle Bin after successful ZIP verification are no longer present in the active results directory. Their mappings may therefore be excluded during a subsequent synchronization. Their ZIP archives remain separate archival copies.

Structural qualification only
Matching chapter numbers and counts do not prove that generated summaries are accurate or complete.

ZIP verification
The ZIP integrity test checks archive readability; it does not validate the content of every chapter.

SHA-256 verification
Matching hashes provide strong confirmation that a backup file is byte-for-byte identical to its source.

Recycle Bin behavior
Recycled folders and duplicate files are generally recoverable through Windows Recycle Bin, subject to Windows settings and subsequent cleanup.

Dropbox synchronization
A successful local copy to the Dropbox-synced directory does not by itself guarantee that cloud synchronization has finished.

Destination replacement
Existing qualified-source destination folders may be replaced using the script's temporary backup and restoration logic. Review destination contents before execution if they contain unique data.

10. AUTOMATIC BOOK-TITLE MAPPING AUDIT AND SYNCHRONIZATION

The book-title mapping file, Chapter Summaries Q&A Books.txt, contains book identifiers and their corresponding titles.

The mapping synchronization stage checks whether each mapped book has a corresponding existing result folder in:

D:\\Box Sync\\ChatGPT Library Results

Matching rule:

A mapping entry is considered matched when its book identifier has an exact corresponding immediate result folder following the Docu_#### naming pattern.

Synchronization process:

1. Read the existing Chapter Summaries Q&A Books.txt file.
2. Identify the book identifier in each valid mapping entry.
3. Scan the immediate result directory for existing folders matching Docu_####.
4. Compare the mapping identifiers with the existing result-folder identifiers.
5. Retain only mapping entries whose corresponding Docu_#### folders exist.
6. Preserve the original book-title text and the relative order of retained entries.
7. Identify existing Docu_#### folders that do not have a corresponding mapping entry.
8. Generate Folder_Mapping_Audit.txt to record the audit results.
9. Preserve a backup copy of the original mapping file before replacing its contents.
10. Write the synchronized mapping entries back to Chapter Summaries Q&A Books.txt.
11. Verify the updated mapping file before allowing the subsequent comparison workflow to use it.

Two important audit outcomes:

A. Mapping entry without an existing folder:
A book-title entry exists in the mapping file, but its corresponding Docu_#### folder does not exist. The entry is excluded from the synchronized mapping file.

B. Existing folder without a mapping entry:
A Docu_#### folder exists, but its identifier does not appear in the mapping file. The folder identifier is recorded in the audit report. The script must not invent or guess a book title for it.

Important rules:
• Matching is based on the exact book identifier, not a guessed or approximate title match.
• Only immediate Docu_#### result folders are considered for this mapping check.
• The original titles and relative order of retained mapping entries are preserved.
• Unmatched folder identifiers are reported rather than silently assigned titles.
• The mapping synchronization stage does not determine whether an ebook passes the chapter comparison rules.
• The synchronized mapping file becomes the mapping input for the subsequent ebook comparison stage.

Important distinction: Mapping synchronization determines which mapped books currently have corresponding result folders. Ebook comparison determines whether those books meet the chapter-document qualification rules. These are separate operations.

12. FILE COPYING, MOVING, AND DELETING

These operations have different effects on files and folders.

Copy: Creates another copy while retaining the original.

Move: Changes the location of a file or folder. After a successful move, the original location no longer contains that item.

Delete: Removes a file or folder from its normal filesystem location.

Recycle Bin: Provides a recovery location for supported Windows deletion operations.

Applications in this project:
• The original mapping file is copied to a backup location before the synchronized mapping replaces it.
• Duplicate Markdown files are moved to the Windows Recycle Bin using send2trash.
• Qualified source ebook folders are moved to the designated E: destination.
• Qualified result folders are moved to the Recycle Bin after successful ZIP verification.
• Done-folder files are copied to Dropbox and deleted from their source locations only after successful backup verification.

Important: Moving, copying, and recycling are different operations. Their failure handling and verification requirements must be considered separately.

Mapping synchronization consideration: Because successfully archived result folders may later be moved to the Recycle Bin, a subsequent mapping audit may no longer find their corresponding Docu_#### folders. Their mapping entries will therefore be excluded in that subsequent synchronization unless the folders have been restored or recreated. This is an expected consequence of the configured matching rule and should be considered when reviewing later workflow executions.
13. UNDERSTANDING FILE SIZE AND MODIFICATION DATE

Python can retrieve file metadata without comparing the complete contents of documents.

File size: The amount of storage occupied by a file, usually measured in bytes.

Modification date and time: Records when a file was last modified according to filesystem metadata.

These properties are used by the duplicate Markdown cleanup process:

3. Retain the largest file.

14. WINDOWS RECYCLE BIN VS. PERMANENT DELETION

Windows supports different ways of removing files and folders.

Move to Recycle Bin:
Moves an item into the Recycle Bin, where it can generally be restored before the bin is emptied.

Permanent deletion:
Removes an item without sending it through the normal Recycle Bin recovery process.

Important considerations:

16. UNDERSTANDING AUTOMATION RULES

Integration testing: Checks whether different parts of the workflow operate together correctly.

Actual execution: Runs the script against the real source and result folders.

28. PRACTICAL EXAMPLE — HOW THE EBOOK WORKFLOW OPERATES

Suppose Chapter Summaries Q&A Books.txt contains these mapping entries:

• 0470: Book A
• 0471: Book B
• 0472: Book C

The result directory contains these immediate folders:

• Docu_0470
• Docu_0472
• Docu_0473

Stage 0 — Mapping audit and synchronization:

The mapping audit compares the identifiers in the mapping file with the existing result-folder identifiers.

Matched mappings:
• 0470: Book A — matching Docu_0470 folder exists.
• 0472: Book C — matching Docu_0472 folder exists.

Mapping entry without an existing folder:
• 0471: Book B — no matching Docu_0471 folder exists.

This mapping entry is excluded from the synchronized mapping file.

Existing folder without a mapping entry:
• Docu_0473 — no 0473 mapping entry exists.

The folder identifier is recorded in the audit report. The script does not invent a title for it.

Updated mapping file:

• 0470: Book A
• 0472: Book C

The original mapping file is backed up before its contents are replaced. The audit report and updated mapping file are checked before the main comparison continues.

Step 1 — Duplicate cleanup:

Suppose the Docu_0470 result folder contains:

• Chapter 01 - Introduction.md
• Chapter 02 - Background.md
• Chapter 02 - Background Copy.md
• Chapter 03 - Conclusion.md

The cleanup process identifies two result files representing chapter 2. It retains the largest file or, if their sizes are equal, the newest file. The remaining duplicate is moved to the Recycle Bin.

Step 2 — Chapter comparison:

Suppose the source folder contains:

• Chapter_01.txt
• Chapter_02.txt
• Chapter_03.txt

After duplicate cleanup, the comparison process checks the remaining source and result chapters:

• Source: 1, 2, 3.
• Result: 1, 2, 3.

Step 3 — Qualification:

If all other qualification conditions are also satisfied, the ebook qualifies.

Step 4 — Source relocation:

The qualified source folder is moved to the configured E: destination.

Step 5 — Result archiving:

The qualified result folder is compressed into a ZIP archive in the Dropbox tables directory.

Step 6 — ZIP verification:

The archive is tested for integrity. Only after successful verification is the original result folder moved to the Recycle Bin.

Step 7 — Done-folder backup:

Eligible Done-folder files are copied to Dropbox and verified using SHA-256 before their source copies are deleted.

Next execution consideration:

Because Docu_0470 and other successfully archived result folders may have been moved to the Recycle Bin, a later mapping synchronization will not find those folders in the active result directory. Their mapping entries will consequently be excluded from the next synchronized mapping file unless the folders have been restored or recreated.

This example illustrates how mapping synchronization, duplicate cleanup, comparison, qualification, relocation, archiving, and backup form a sequential automation workflow.
